**Changes versus upstream, and why.**
- One job instead of `build` → `test`: no artifact upload/download and no `tar`; the same commands run in the same order, each with its original job's env (step-level env on the precompile step).
- No caches: bundler (`bundler-cache`), yarn, assets (`public/assets public/packs* tmp/cache/vite`), RSpec persistence (`tmp/rspec/examples.txt`) — the persistence file only feeds `--only-failures`-style ordering; the set of examples is the same.
- apt: the Azure-mirror `sed` runs only if `/etc/apt/apt-mirrors.txt` exists (a GitHub-image file; `sed -i` on a missing file fails); `libyaml-0-2 libgmp10` added — ruby/setup-ruby's documented runtime prerequisites on self-hosted runners, already installed on GitHub's images (no-op there).
- `bundle install` written out with the commands `bundler-cache: true` runs (path, deployment, `--jobs`).
- `bin/flatware rspec` output tee'd to a file (`shell: bash` keeps the exit status). No Codecov step. `timeout-minutes: 120` (upstream: 15 + 60).

**Third-party actions needed.** `ruby/setup-ruby@v1` (upstream's `setup-ruby` composite uses it). Self-hosted Ubuntu 26.04: supported — README "Supported Platforms" lists `ubuntu-22.04`, `ubuntu-24.04`, `ubuntu-26.04` (x64 and arm64); `common.js` accepts `ubuntu-26.04-x64` read from `/etc/os-release`; prebuilt tarballs exist in the ruby/ruby-builder release `ruby-4.0.7` (2026-09-15) for `ubuntu-24.04-x64` (49.0 MB) and `ubuntu-26.04-x64` (49.8 MB), so the GitHub legs and ICR all download a prebuilt Ruby. README conditions for self-hosted runners: same OS release as a GitHub image, same libssl (libssl3), `libyaml-0-2` and `libgmp` installed (done by the apt step), `/opt/hostedtoolcache` and `/home/runner` writable by the runner user (the Ruby build embeds its install path). GitHub-owned: `actions/setup-node@v6`.

**Memory/disk risks.** Vite production build: 2–3 GiB of Node heap; flatware: one Rails process per CPU (0.6–1 GiB each) plus Postgres and Redis (small) → `icr-2c` (8 GiB, 2 workers) and `icr-8c` (32 GiB, 8 workers) both fit. Disk ~6 GB (`node_modules` ~1.5 GB, `vendor/bundle` ~1 GB, ffmpeg and its libraries ~0.3 GB). PostgreSQL 14's default `max_connections=100` covers 8 workers.

**What may fail on the ICR image, fix applied.** (a) ruby/setup-ruby refuses the runner if `/etc/os-release` is not exactly Ubuntu 26.04 or if the tool cache is not writable — no workaround in the workflow; the README's requirements are listed above for the image maintainer. (b) apt package names on Ubuntu 26.04: `libidn11-dev` and `libvips42` are transitional/provided names on 24.04 (real packages `libidn-dev`, `libvips42t64`); if 26.04 dropped them, the apt step fails on `ubuntu-26.04` and ICR alike and the fix is those two names — not applied, upstream's list is kept until a run shows it. (c) `sudo apt-get` requires passwordless sudo and outbound apt access. (d) The Azure-mirror rewrite — guarded. (e) Corepack downloads yarn 4.18.0 from the npm registry on first use (no prompt without a TTY), the same on both sides.
